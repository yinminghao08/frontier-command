# 2026-10-08 消息与任务反馈修订验证

明确 Admiral 任务现在由独立的短 LLM 请求判断接受或拒绝，不再发送等待任务提议的聊天占位回执，也不进入新的条件协商。接受结果通过既有命令校验，并立即交给真实任务执行器；暂停时可以下达指令，物理模拟仍只在游戏时间推进时执行。普通交流和同僚协作保留原完整模型决策。

在同一个隔离初始世界、同一条“巡逻基地 5 分钟”指令上，捕获完整 HTTP JSON 请求体进行比较：旧完整决策 97,605 bytes；短任务判断 3,581 bytes，减少约 96%。测量没有连接外部 API。真实供应商网络和推理延迟未在本次验证中测量。

应用内每分钟额度、全局并发上限、单次决策最多三条消息均已移除；旧 agent-runtime.v1.json 不再读取。只保留遥测、每 Agent 一个有效决策、过期请求取消、认证失败保护与自动错误退避。新的玩家输入可打断暂时错误退避。聊天历史仍完整保存，模型观察窗口、单条长度与传输响应大小约束保留。

缺弹通知改为每艘舰船的持久状态：同一次持续缺弹只提醒一次；两种弹药均恢复至配置阈值后解除，再次缺弹才重新提醒。恢复检查在直接指挥与 Agent 控制的提前返回之前执行。旧存档缺少字段时根据当前缺弹和旧 ammoReport 记录初始化，避免升级重启后重复报告。

## 验证结果

- 最后一次全量 Vitest：23 个文件，310 项通过。
- 最终生产构建：TypeScript、Vite、Electron 编译通过。
- 首轮相关 Electron：9 项中 8 项通过。失败项发现模型输出校验耗尽未计入错误遥测；已补全失败计数。
- 最终构建重点 Electron 复验：短 LLM 接受/拒绝、无调用额度及旧额度文件失效、缺弹跨时间推进/改名/重启，3/3 通过（58.6 秒）。

- 所有 Electron 场景使用隔离 userData 和 localhost Provider；未读取玩家 API Key、未调用玩家外部模型、未修改实际游戏存档。
